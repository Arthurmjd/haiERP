# 海岚 ERP 业务逻辑图

依据当前代码整理，供组内讨论、开发和联调使用。图片是业务记忆图；下方 Mermaid 图给出准确的单据关系与状态条件。首期范围是单工厂、单仓库、B2B 服装业务；一个订单可有多个款式和色码，一个订单款式对应一个工单。

## 1. 主业务闭环

```mermaid
flowchart LR
    A[基础档案<br/>客户、款式、SKU、BOM、工序、物料] --> B[销售订单草稿]
    B --> C[确认订单<br/>冻结色码、数量、单价、交期]
    C --> D[净缺料建议]
    D --> E[采购草稿与下单]
    E --> F[按明细分批收货<br/>物料入库]
    C --> G[按订单款式建工单<br/>冻结 SKU、BOM、工价]
    F --> H[现存物料齐套]
    G --> H
    H --> I[领料、报工、完工<br/>合格成品入库]
    I --> J[按 SKU 和批次分批发货]
    J --> K[订单各 SKU 发齐]
    K --> L[标准成本确认]
    L --> M[引用已确认成本生成新报价]
    J --> N[签收]
    J --> O[退货登记与处理]
    I --> P[计件明细与工资单]
    C --> Q[看板、规则预警、受控 AI 问答]
    D --> Q
    J --> Q
    L --> Q
```

**关键区别：**采购建议考虑已下单未收货的在途量，但工单领料只认现存库存。成本可以先试算；确认必须等工单完工且该订单款式全部发齐。签收是出货单的后续状态，与“发齐”分别记录。

## 2. 接单与备料

![小黑量出订单的净缺口](../assets/hai-erp-business-illustrations/01-order-to-procurement.png)

```mermaid
flowchart LR
    A[维护款式、色码、BOM、物料与供应商] --> B[创建订单草稿]
    B --> C{订单有效且明细不重复?}
    C -- 否 --> B
    C -- 是 --> D[确认订单]
    D --> E[计算剩余物料需求]
    E --> F[减现存库存]
    F --> G[减已下单未收货量]
    G --> H{有净缺口?}
    H -- 是 --> I[生成采购草稿]
    I --> J[确认下单<br/>开始计入在途]
    J --> K[按采购明细分批收货]
    K --> L[物料结存增加并生成入库流水]
    H -- 否 --> M[已有可用物料]
    L --> M
```

净缺口 = 活动订单 BOM 剩余需求 - 现存库存 - 已下单未收货数量；订单需求先扣已领料。采购草稿不计入在途，部分收货后只把未收部分算在途。收货不能超过采购明细的未收量，重复 `requestKey` 不重复入账。

## 3. 工单、库存与人事

![小黑踩动工单机器](../assets/hai-erp-business-illustrations/02-production-and-stock.png)

```mermaid
flowchart LR
    A[已确认订单] --> B[按订单款式建工单]
    B --> C[冻结 SKU 计划、BOM 用量、工序工价]
    C --> D{现存物料齐套?}
    D -- 否 --> E[等待采购收货]
    E --> D
    D -- 是 --> F[下达领料<br/>扣物料库存并记流水]
    F --> G[逐工序、逐 SKU 报工]
    G --> H[合格数计进度和员工计件]
    G --> I[不良数单独记录<br/>不计件、不入成品]
    H --> J{最终工序合格数足够?}
    J -- 是 --> K[按 SKU、批次完工入库]
    K --> L[成品结存增加并记流水]
    H --> M[按员工和工资期生成工资草稿]
    M --> N[核对计件后确认工资]
```

领料不能使用在途量；工序合格数不能超过 SKU 计划量或上一工序合格数。完工入库量不能超过最终工序累计合格数及冻结计划数。报工产生的内部员工计件记录供工资单汇总；确认后的工资期不能补录报工。采购收货、领料、完工、发货、退货回库和盘点差异都留下库存流水。

## 4. 分批出货与退货

![小黑把一张订单分批送出](../assets/hai-erp-business-illustrations/03-shipping-and-return.png)

```mermaid
flowchart LR
    A[工单产生成品库存] --> B[按订单 SKU 与库存批次建出货草稿]
    B --> C{未发订单量和批次库存足够?}
    C -- 否 --> B
    C -- 是 --> D[发货出库<br/>扣成品库存并记流水]
    D --> E{订单全部 SKU 累计发齐?}
    E -- 否 --> B
    E -- 是 --> F[订单记为已发齐<br/>记录最后一批发货日期]
    D --> G[出货单签收]
    G --> H[全部出货单签收后订单完成]
    D --> I[按原出货单登记退货]
    I --> J{退货类型要求回库?}
    J -- 是 --> K[核对未退数量并回库记流水]
    J -- 否 --> L[登记处理结果]
```

部分发货不等于已发齐；不能超订单 SKU 未发量，也不能扣成负库存。退货按原出货的 SKU、批次和剩余可退数量核对；符合回库条件时才增加库存。当前退货处理不会自动创建换货发运，也不会冲回已经确认的标准成本。

## 5. 标准成本与下一次报价

![小黑称量并锁定标准成本](../assets/hai-erp-business-illustrations/04-cost-to-quotation.png)

```mermaid
flowchart LR
    A[订单约定收入] --> D[按订单 × 款式试算]
    B[冻结 BOM 数量 × 物料参考价快照] --> D
    C[冻结工序数量 × 工价快照] --> D
    E[材料与人工之和 × 费用率] --> D
    D --> F[成本明细、单位成本、标准毛利]
    F --> G{工单完工且该款式发齐?}
    G -- 否 --> H[保留试算草稿]
    G -- 是 --> I[确认并冻结标准成本]
    I --> J[引用已确认结算生成报价]
    J --> K[报价待确认 → 已接受或已失效]
```

试算草稿可重算；已确认结算不可覆盖。这里是**标准成本**，不是实际领料成本、实发工资或退款后的净利润。报价引用的是已确认结算的成本快照，并保存来源。

## 6. 看板、预警与 AI

![小黑从有权限的抽屉取出业务记录](../assets/hai-erp-business-illustrations/05-ai-and-alerts.png)

```mermaid
flowchart LR
    A[用户选择订单、库存、缺料、成本或交付] --> B{登录且具有对应读权限?}
    B -- 否 --> C[拒绝访问]
    B -- 是 --> D[运行预设只读 SQL<br/>最多返回 20 条]
    D --> E{DeepSeek 密钥可用?}
    E -- 是 --> F[模型依据记录生成简短解释]
    E -- 否或超时 --> G[返回确定性数据摘要]
    F --> H[答案 + 原始记录 + 来源 + 数据时间]
    G --> H
    I[缺料与逾期规则] --> J[可复算预警]
    J --> K[可选模型解释<br/>不可用时返回规则说明]
```

ERP 业务问答不是 RAG，也不会让模型生成 SQL 或执行单据动作。查询范围固定为订单、库存、净缺料、款式成本、发齐准交率五档，先校验工作台权限再按范围映射业务读权限，预设只读 SQL 最多返回 20 条。预警先由业务 SQL 规则计算，当前代码提供缺料和逾期未发齐两类。模型不可用或超时时降级为规则摘要（`modelUsed=false`），前端只渲染真实接口数据，不再有浏览器内的模拟数据分支。

## 7. 岗位接力

| 岗位 | 主要接力点 |
| --- | --- |
| 销售 | 客户、报价（新建/编辑/成交/转订单）、订单、交付跟踪、出货与退货 |
| 计划员 | 主数据维护、净缺料、采购建议、采购下单与收货、工单准备 |
| 仓管员 | 采购收货、库存结存与流水、领料、成品和出退货、库存调整 |
| 生产主管 | 工单、工序派工、领料、工序报工、完工入库、退料 |
| 人事 | 员工档案、计件核对、工资单生成（单条/批量）、确认与查询 |
| 财务 | 成本试算与确认、资金账户、应收应付、收付款登记与确认、会计期间结账、工资发放 |
| 厂长 | 经营看板、采购审批通过/驳回、资金只读、交付风险与授权范围内的业务问答 |
| 管理员 | 平台用户、角色、权限与全流程维护 |

所有岗位使用同一网址。工作台和导航随角色变化，真正的数据与操作权限由后端校验；权限不足返回 HTTP 200 + 响应体 `code=403`。业务动作的 `requestKey`、状态更新和库存/计件副作用在事务中处理，并发、权限与对账已由 `sql/self_check.sql`（29 项）、`p2`（9 项）、`p3`（15 项）、`p4`（7 项）覆盖。
