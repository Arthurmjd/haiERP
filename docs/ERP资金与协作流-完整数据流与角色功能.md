# 海岚 ERP：资金与协作流 —— 完整数据流与角色功能

> 版本：v1.0（2026-10-26）。本文描述 P0 改造后的目标数据流、会计口径、角色职责与交接点。
> 实现状态：数据库脚本、后端服务/接口已完成并通过 Maven 编译与现有单测；前端页面代码已生成且 `npm run build` 通过，真实数据库联调待验证。

---

## 1. 设计原则

1. **权责发生制 + 收付实现制双视角**：业务事件确认应收应付；只有收付款才动资金账户。
2. **订单确认不产生资金**：发货确认应收，收款才增加资金；收货确认应付，付款才减少资金。
3. **一单到底**：下游单据携带来源 ID，可追溯到订单、采购、工单、出货。
4. **自动交接**：每个业务动作在同一事务内生成下一棒待办，角色不必靠人喊。
5. **只增不改**：资金流水、库存流水、报工与计件只增；错账走红字冲销。
6. **冻结优先**：工单冻结 BOM/工价，成本结算冻结价格快照，期间结账后禁止补录。
7. **成本不等于资金**：标准成本结算永远不产生资金流水。

## 2. 端到端数据流

```
                     ┌──────────────── 会计中心 ────────────────┐
                     │ 资金账户 / 收支流水 / 应收 / 应付 / 收付款 │
                     └──▲───────────▲──────────────▲───────────┘
                        │收款        │付款          │发工资
销售 ─报价─▶ 订单确认 ─▶ MRP ─▶ 采购下单 ─▶ 收货 ─▶ 应付 ────────┘
  │            │            │(厂长阈值审批)   ▲
  │            │            ▼                │
  │            │        工单下达 ─▶ 领料 ─▶ 报工 ─▶ 计件工资 ─▶ 工资单(计提)
  │            │            │                          │
  │            │            ▼                          │
  │            │        完工入库                       │
  │            │            │                          │
  └─发货 ─▶ 应收 ─▶ 收款 ───┘                          │
       │                                               │
       └─▶ 标准成本结算（毛利）◀───────────────────────┘
```

### 2.1 事件触发矩阵

| # | 业务事件 | 执行角色 | 会计动作 | 资金动作 | 自动下一棒 |
|---|---|---|---|---|---|
| 1 | 报价草稿 → 已接受 | sales | 无 | 无 | 可转订单 |
| 2 | 销售订单确认 | sales | 无（仅承诺，可选信用校验） | 无 | planner：采购/排产 |
| 3 | 采购单提交 | planner | 超阈值转厂长审批 | 无 | boss：审批 |
| 4 | 采购审批通过 | boss | 无（承诺） | 无 | wh：收货 |
| 5 | 采购收货 | wh | 应付↑、存货↑ | 无（账期） | finance：付款 |
| 6 | 付款确认 | finance | 应付↓ | 账户↓、流水 | 完成待办 |
| 7 | 工单下达 | planner/production | 无 | 无 | production：领料 |
| 8 | 领料 | production/wh | 原材料→在制 | 无 | production：报工 |
| 9 | 报工 | production | 计件工资计提 | 无 | 月末工资 |
| 10 | 完工入库 | production/wh | 在制→库存商品 | 无 | sales：可出货 |
| 11 | 销售发货 | wh | 应收↑、收入↑ | 无（账期） | finance：收款；sales：签收 |
| 12 | 收款确认 | finance | 应收↓ | 账户↑、流水 | 完成待办 |
| 13 | 客户签收 | sales/wh | 无 | 无 | 订单完成 |
| 14 | 成本结算确认 | finance | 标准成本/毛利快照 | 无 | 可生成新报价 |
| 15 | 工资单确认 | hr | 应付职工薪酬↑ | 无 | finance：发放 |
| 16 | 工资发放 | finance | 应付薪酬↓ | 账户↓、流水 | 完成待办 |
| 17 | 退货处理 | sales/wh | 收入↓、应收冲减 | 退款另走付款 | finance：退款处理 |
| 18 | 期间结账 | finance | 锁定当月 | 无 | 禁止补录 |

## 3. 各角色功能与交接

### 3.1 销售 sales
- 客户档案、报价（手工新建/引用结算生成）、报价接受/失效、报价转订单。
- 销售订单草稿/编辑/确认；确认后冻结色码、数量、单价、交期。
- 出货单建单；查看签收状态；退货登记。
- 收到「订单已完工，可安排出货」「待签收」待办。
- 不接触资金与成本。

### 3.2 计划员 planner
- 查看 MRP 净缺料；从缺料建议生成采购草稿。
- 采购单建单/编辑/提交；超阈值进入厂长审批，待审批不计在途。
- 按订单款式建工单；支持一键生成该订单全部款式工单。
- 工单自动排期（按订单交期倒排 7 天）。
- 收到「订单已确认」「采购被驳回」待办。

### 3.3 生产主管 production
- 工单领料（支持分批、按物料选择）；查看预留与可用量。
- 报工：按工序×SKU×员工录入合格/不良，前后工序数量卡控。
- 退料：生产中把未用物料退回仓库。
- 完工入库：受最终工序合格数封顶。
- 收到「领料」「报工」待办。

### 3.4 仓管 wh
- 采购收货（分批、按明细行、写流水）；超收拒绝。
- 发料、完工入库、销售发货、退货回库、盘点调整。
- 不接触资金；收货后自动形成应付与会计付款待办。
- 收到「待收货」待办。

### 3.5 人事 hr
- 员工档案、部门/岗位、计件明细查询。
- 月度工资单：按基本工资 + 计件 + 补贴 + 加班 − 社保/公积金/个税。
- 批量生成全员工资单；确认后进入待发放（不直接视为已发）。
- 收到「待办」；工资发放由会计执行。

### 3.6 会计 finance（原「财务」）
- 资金账户维护（现金/银行/电子），期初与当前余额。
- 资金流水查询；应收/应付台账与账龄。
- 登记收款/付款并核销 AR/AP；确认后过账。
- 工资发放：确认后的工资单生成付款并过账。
- 标准成本试算/确认；期间结账/反结账。
- 收到「付款」「收款」「工资发放」待办。

### 3.7 厂长 boss
- 审批中心：采购超阈值审批/驳回。
- 经营看板：现金余额、本月流入流出、应收应付、逾期、标准毛利、准交率。
- 预警解读（AI 只解释，不改业务状态）。
- 只读为主，不接触工资明细。

### 3.8 管理员 admin
- 主数据（款式/BOM/工序/物料/供应商/客户/SKU）——日常维护已下放给计划员 `planner`，admin 保留兜底。
- 角色、菜单、权限点、单据号、字典、参数（系统管理四模块只授 admin）。
- 期间反结账、审计日志、业务动作幂等记录。

> 本节描述的角色能力与 `sql/erp-permissions.sql` + `sql/p4-rbac-completion.sql` 下发的授权一致；`p4` 自带 7 项自检，确保「财务能登记收付款」「销售能新建报价」「厂长资金只读」这些边界不会被后续维护改坏。

## 4. 数据模型（P0 新增）

| 表 | 用途 |
|---|---|
| `fn_account` | 资金账户，期初/当前余额 |
| `fn_cash_txn` | 只增资金流水，幂等键唯一 |

## 5. 状态机

| 单据 | 状态 |
|---|---|
| 报价 | 0待确认 → 1已接受 / 2已失效 |
| 销售订单 | 0草稿 → 1已确认 → 2生产中 → 3已完工 → 4已发齐 → 5已完成；9取消 |
| 采购单 | 0草稿 →（approval_status：0无/1待审/2通过/3驳回）→ 1已下单 → 2部分收货 → 3全部收货 |
| 工单 | 0待下达 → 1生产中 → 2已完工；9取消 |
| 出货单 | 0草稿 → 1已发货 → 2已签收 |
| 退货单 | 0待处理 → 1已处理 |
| 工资单 | 0草稿 → 1已确认 → 2已发放 |
| 应收/应付 | 0未收付 → 1部分 → 2已结清；9作废 |
| 收付款 | 0草稿 → 1已确认（过账） |

## 7. 边界

- 首期不做复式记账/总账、发票、预算、多仓、APS 排产、质检返修、条码。
- 标准成本仍不等于实际成本；实际计件与标准人工差异由 `v_labor_variance` 单列。
- 退款只冲减应收；不足部分生成退款待办，由会计走付款流程。
- 库存预留为工单锁料，MRP 仍按库存+在途估算，后续可把预留纳入供给口径。
