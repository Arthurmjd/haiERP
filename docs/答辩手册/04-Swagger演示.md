# 04 · Swagger 接口文档：怎么打开、怎么演示

> 用途：答辩时被问「你们接口是怎么设计的/有没有接口文档」时，直接打开页面点给他看。
> 全程只需要一个网址，不需要装任何东西。

---

## 一、先记住这一个网址

后端启动后，浏览器打开：

```
http://127.0.0.1:8080/swagger/
```

下面这几种写法**都能打开**（已经做了跳转，带不带斜杠都行，现场不用纠结）：

- `http://127.0.0.1:8080/swagger`
- `http://127.0.0.1:8080/swagger/`
- `http://127.0.0.1:8080/doc` ← **短地址，口头念最省事，推荐记这个**

> 如果 8080 被别人占了改过端口，把端口换掉即可。

配套的两个地址（老师如果问「文档从哪来的」可以给他看）：

| 地址 | 是什么 |
|---|---|
| `http://127.0.0.1:8080/v3/api-docs` | 全部接口的 OpenAPI 3.1 规范 JSON（405 条路径） |
| `http://127.0.0.1:8080/v3/api-docs/05 出货：发货与退货` | 单个业务域的规范（浏览器会自动 URL 编码；界面里直接点下拉更省事） |

**打开前提**：后端已经起来。可以双击 `scripts/start-all.bat`，也可以在 `backend` 目录下
`java -jar myfactoryai-admin/target/myfactoryai-admin.jar`。

## 二、页面上你会看到什么（先说清楚，别现场懵）

打开后大致是这样：

```
┌──────────────────────────────────────────────────────────────┐
│ 海岚 ERP · 服装制造企业资源计划 接口文档        [Authorize]  │  ← 右上角认证按钮
├──────────────────────────────────────────────────────────────┤
│ 分组下拉：全部接口（按 Tag 分组）  ▼                         │  ← 11 个入口
│                                                              │
│ ▼ 全部接口（按 Tag 分组）                                    │
│   GET  /erp/sd/order/list        查询销售订单列表   [Try it out] │
│   POST /erp/sd/order             新建销售订单       [Try it out] │
│   ...                                                        │
│ ▼ Schemas     ← 数据结构定义（订单、库存行等字段）            │
└──────────────────────────────────────────────────────────────┘
```

三个要点：

1. **左上角分组下拉**：默认是「全部接口（按 Tag 分组）」，405 条路径；往下是 10 个业务域：
   01 销售 / 02 采购 / 03 生产 / 04 库存 / 05 出货 / 06 财务 / 07 人事 / 08 主数据 /
   09 系统与权限 / 10 看板与 AI 问答。答辩时先停在「全部接口」讲规模，再切到具体域点接口。
2. **每个接口卡片**：方法（GET/POST）+ 路径 + 说明，右下角有 `Try it out`（调试）。
3. **右上角 `Authorize`**：贴 token 的地方，不贴就只能看到文档、调不动接口（会返回未认证）。

## 三、三步拿到 token 并认证（关键，30 秒）

本项目所有业务接口都要 JWT，所以要先登录拿 token。

### 第 1 步：在 Swagger 里直接调登录接口

1. 分组下拉选 **09 系统与权限**（或者用浏览器 `Ctrl+F` 搜 `login`）；
2. 找到 `POST /login`，点 **Try it out**；
3. 把 Request body 改成（账号密码照抄，密码统一 `Demo@2026!`）：

```json
{
  "username": "sales",
  "password": "Demo@2026!"
}
```

4. 点蓝色 **Execute**；
5. 下面 **Server response** 里会出现 `Code: 200` 和一段返回，形如：

```json
{
  "msg": "操作成功",
  "code": 200,
  "token": "eyJhbGciOiJIUzUxMiJ9.eyJsb2dpbl91c2VyX2tleSI6..."
}
```

6. 把 `token` 后面那串**长字符串整个复制**（一定不要带引号、不要带 `Bearer `）。

### 第 2 步：贴到 Authorize

1. 点右上角 **Authorize**（有个小锁图标）；
2. 弹窗里只有一个 `Value` 输入框，把 token 粘进去；
3. 点 **Authorize** → 再点 **Close**。

> 现在锁图标变成「已锁定」状态，所有接口的 `Try it out` 都会自动带上
> `Authorization: Bearer <token>`。刷新页面也不用重新贴（页面开了持久化）。

### 第 3 步：验证一下通了

分组切到 **01 销售：报价与订单** → `GET /erp/sd/order/list` → Try it out →
`pageNum` 填 1、`pageSize` 填 3 → Execute。

返回 `Code: 200`，body 里是：

```json
{ "total": 44, "rows": [ ... ], "code": 200, "msg": "操作成功" }
```

看到 `rows` 有数据就说明认证成功，可以开始演示了。

## 四、演示动线（3～5 分钟，跟着主线走）

顺序是设计好的：**先看文档规模 → 再看两个真实业务接口 → 最后用权限对比收尾**。

### ① 先讲规模（10 秒，不用点）

> 「接口文档是代码注解自动生成的，不是手写的。左边分组按 9 个业务域切开，
> 全部 260 个方法级接口、228 处权限注解都在这里，规范和代码永远同步 ——
> 改了接口文档自动跟着变，不会出现文档过期的问题。」

### ② 看出货批次接口（30 秒，这条是刚修好的，能讲出故事）

分组 **05 出货** → `GET /erp/sh/shipment/batches` → Try it out → `skuIds` 填 `1` → Execute。

返回：

```json
[
  { "skuId": "1", "batchNo": "C20261020", "qty": 5.0 },
  { "skuId": "1", "batchNo": "FG26-001-A", "qty": 80.0 }
]
```

> 「这个是做出货单时给仓管员选批次的接口。之前批次是手打的，打错一个字就发不了货，
> 而且提示只有一句『成品库存不足』，看不出是批号错了还是数量不够。
> 现在改成后端直接返回可用批次和结存，前端做下拉，报错也会说清楚
> 『没有批次 X 的库存，当前可用批次是 A、B』。」

### ③ 看销售订单列表（30 秒，讲两种响应包络）

`GET /erp/sd/order/list`，注意返回是 `total` + `rows`（分页包络），
而单个对象接口（如 `GET /erp/sd/order/{id}`）返回的是 `data`。

> 「我们有两种响应包络：列表是 `rows`+`total` 给表格分页用，单对象是 `data`，
> 前端 `api/erp.ts` 里统一封装了解析，页面不用各自判断。」

### ④ 权限对比（1 分钟，最出彩的一段）

现在 token 是 `sales` 的，去调一个财务接口：

分组 **06 财务** → `POST /erp/fn/settlement/calc` → Try it out → body 填：

```json
{ "orderId": 1, "styleId": 1, "requestKey": "demo-403" }
```

Execute，结果会是 **HTTP 200，但 body 里 `code` 是 403**：

```json
{ "code": 403, "msg": "没有权限，请联系管理员授权" }
```

> 「注意这里 HTTP 状态码是 200，权限不足写在 body 的 `code` 里。
> 这是我们统一的约定 —— 因为前端拦截器按 `code` 判断，业务失败和权限失败走同一套提示，
> 不会出现有的地方弹窗、有的地方白屏。刚才这个接口挂的是 `fn:settlement:calc`，
> 销售账号没有这个权限点，所以被挡在方法入口，业务代码一行都没执行。」

如果想演示「有权限就能过」，换 `finance` 账号重新登录拿 token 再来一次即可（同一个接口会返回 200 并生成结算单）。

### ⑤（可选）Schemas 展示数据结构

页面底部 **Schemas** 展开，可以看到 `OrderDraftRequest`、`ShipmentRequest` 等请求体的字段定义。

> 「请求体也是强类型的 Java record，字段名、类型、是否必填在文档里一目了然，
> 前端照着这个写表单，不用来回问后端要字段。」

## 五、可能被追问的问题（准备好答案）

| 老师可能问 | 怎么答 |
|---|---|
| 文档是手写的吗？ | 不是，`springdoc-openapi` 扫描控制器和注解自动生成，代码即文档 |
| 怎么保证文档不过期？ | 文档跟着代码编译生成，改接口自动变；另外 32 个单测里有一条反射扫描所有 `@PreAuthorize`，防止注解被误删 |
| 为什么用 Swagger 3 / OpenAPI 3？ | 项目是 Spring Boot 3.5 + JDK 21，老的 springfox 不支持，官方推荐 springdoc |
| 生产环境也开着吗？ | 不开，`SWAGGER_ENABLED=false` 一个环境变量就关掉了，避免暴露内部接口 |
| 权限是在文档里配的吗？ | 不是，权限在方法上的 `@PreAuthorize`，文档只是把它展示出来 |
| 这个页面能调试吗？ | 能，`Try it out` 发的是真实请求，会真的写库（所以我在演示库上点） |

## 六、现场故障速查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `{"msg":"No static resource swagger.","code":500}` | 少写斜杠，且后端还是旧版本 | 已修：三种写法都能进；用最新 jar 重启即可 |
| `{"msg":"接口或资源不存在：/xxx","code":404}` | 路径写错了 | 回文档里复制准确路径，别手打 |
| 页面显示 `No API definition provided.` | 页面拿不到接口定义（旧版本用 configUrl，而那个接口已随官方 UI 一起下线） | 已修：分组清单写进页面，用最新 jar 重启；顺便 `Ctrl+F5` 强刷 |
| 页面空白 / 一直转圈 | 后端没起来，或 8080 被占 | 先访问 `http://127.0.0.1:8080/v3/api-docs`，能出 JSON 就说明后端活着 |
| 页面出来了，但显示 Petstore 示例接口 | 打开了旧地址 `/swagger-ui/index.html` | 用 `/swagger/` 或 `/doc` |
| 点 Execute 返回 401 / `认证失败` | token 没贴、贴过期了、或贴成了带 `Bearer ` 前缀 | 重新走第三节，只复制 token 本身 |
| 点 Execute 返回 403 | 当前账号没有该权限点（正常现象，可用于演示） | 换有权限的账号重新登录 |
| 分组下拉是空的 | `swagger.enabled` 被关了 | 检查 `application.yml` 里 `swagger.enabled` 为 true |
| 中文乱码 | 浏览器编码 | 换 Chrome/Edge，页面本身是 UTF-8 |

**备用方案**（页面实在打不开时）：
打开 `http://127.0.0.1:8080/v3/api-docs` 直接把 JSON 给老师看 —— 405 条路径都在里面；
或者把 JSON 复制到 [editor.swagger.io](https://editor.swagger.io) 里粘贴，同样能渲染成界面。
