## 3. 登录到首页：一条链路讲完权限

### 3.1 登录

`LoginView.vue` → `user.login()`（`stores/user.ts`）：

```ts
const result = (await http.post('/login', { username, password, code, uuid })).data
token.value = result.token      // 注意：token 在响应体顶层，不在 data 里
setToken(result.token)          // 写 localStorage，键 hai-erp-token
```

验证码是**可开关**的：先调 `/captchaImage`，返回 `captchaEnabled=false` 就不渲染验证码输入框（演示库现在是关的），代码还留着，打开配置就能用。

### 3.2 拿用户与权限

首次进入受保护路由时，守卫调 `user.load()`：

```ts
const info = (await http.get('/getInfo')).data
name.value = info.user.nickName || info.user.userName
roles.value = info.roles || []
permissions.value = info.permissions || []
```

`roles` 和 `permissions` 也都在**顶层**，这是 RuoYi 的约定，所以不能写一个全局 `return res.data.data` 把它们统一剥一层 —— 这是本项目请求层最重要的一条纪律。

### 3.3 权限匹配（含通配）

```ts
function permissionMatches(granted: string, required: string): boolean {
  if (granted === required) return true
  if (!granted.includes('*')) return false
  const pattern = '^' + granted.split('*').map(escape).join('.*') + '$'
  return new RegExp(pattern).test(required)
}
function can(permission: string) { return permissions.value.some(g => permissionMatches(g, permission)) }
```

为什么要通配：管理员账号的权限是 `*:*:*` 一条，如果不支持通配，就得给管理员配几百条权限。用"把 `*` 转成 `.*` 拼正则"实现，几行代码解决。

### 3.4 权限在前端生效的三处

| 位置 | 代码 | 效果 |
|---|---|---|
| 路由守卫 | `router.ts` 的 `beforeEach`：`if (permission && !user.can(permission)) return { name: 'forbidden' }` | 直接输 URL 也进不去 |
| 侧边栏 | `App.vue`：`links.filter(link => user.can(link.permission))` | 没权限的菜单不渲染 |
| 页面按钮 | `v-if="user.can('sd:order:confirm')"` | 按钮不出现 |

**必须补一句**（这是得分点）：这三处都只是"不渲染"，绕过它们直接打接口照样会被后端拦住 —— 前端权限是体验，后端权限才是安全。

### 3.5 岗位视角切换

`roles.ts` 里每个角色有一份 `roleProfiles`：`label`（显示名）、`heading`（首页标题）、`focus`（一句话定位）、`navigation`（优先导航顺序）。

`App.vue` 用它把菜单分成两段：

- `primaryLinks` = `profile.navigation` 里**你有权限**的那些（按岗位顺序）
- `secondaryLinks` = 其余有权限的入口（补齐，不丢功能）

所以同一个 `sales` 账号和 `admin` 账号，看到的侧边栏顺序和首屏标题都不一样，但**能点什么是权限决定的，顺序只是组织方式**。

## 4. 请求层：两种响应包络 + 三种错误

`api/client.ts` 只有 59 行，但把最难缠的部分都收在这里了。

```ts
export const http = axios.create({ baseURL: '/api', timeout: 15000 })

// 请求：自动加 Token
http.interceptors.request.use(config => {
  const token = getToken()
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

// 响应：业务码不是 200 就当错误
http.interceptors.response.use(response => {
  const value = response.data
  if (!value || value.code !== 200) {
    if (value?.code === 401) { clearToken(); window.dispatchEvent(new Event('erp-unauthorized')) }
    throw new ApiError(value?.msg || '请求失败', { status: response.status, code: value?.code })
  }
  return response
}, error => { /* HTTP 层错误：401 掉登录态、403 提示无权限、其余取 msg */ })
```

**为什么不能"HTTP 200 就当成功"？** 因为 RuoYi 的权限不足返回的是 **HTTP 200 + 响应体 `code=403`**。只看 HTTP 状态码会把"没权限"当成"成功但没数据"。

两种包络的取值方式：

| 返回类型 | 形状 | 取值 |
|---|---|---|
| `AjaxResult` | `{ code, msg, data }` | `payload(http.get(...))` → 返回 `data` |
| `TableDataInfo` | `{ code, msg, rows, total }` | 直接取 `rows` / `total`，`total` 过 `pageTotal()` |

`pageTotal()` 干一件小事但很重要：`total` 如果是字符串就转数字，**不是安全整数就抛错**。因为 BIGINT 主键序列化时可能是字符串，直接拿去算分页会出精度问题。

401 的处理是全局的：清 token + 派发 `erp-unauthorized` 事件，`router.ts` 监听后跳登录页。

## 5. 配置驱动的列表页（最值得讲的设计）

### 5.1 一句话

> **加一个列表页 = 加一段配置 + 一条菜单，不新建 Vue 文件。**

### 5.2 配置长什么样

`api/catalog.ts` 里每个列表页就是一个对象：

```ts
styles: {
  title: '款式',
  path: '/erp/md/style/list',
  permission: 'md:style:list',
  columns: [
    { prop: 'code', label: '编码', width: 150 },
    { prop: 'name', label: '名称' },
    { prop: 'season', label: '季节' },
    { prop: 'status', label: '状态', enum: 'masterStatus' }   // ← 列上声明枚举，自动出标签
  ]
}
```

字段含义：

| 字段 | 作用 |
|---|---|
| `title` / `path` / `permission` | 页面标题、列表接口、进入该页需要的权限 |
| `columns` | 列定义，`enum` 指向 `labels.ts` 里的枚举键，渲染成彩色标签 |
| `detailRoute` + `detailPermission` | 有值就支持"点行进详情"，路由由 `router.ts` 自动生成 |
| `filter: 'month'` | 顶部出现年月选择器，把 `YYYY-MM` 传给后端（工资单、计件、工单、出货、流水五个列表用到） |

`catalogs` 按业务域分组（`master` / `hr` / `sales` / `production` / `inventory` / `shipping` / `cost` / `reports`），URL 是 `/:group/:key`，例如 `/master/styles`、`/hr/salary`。

### 5.3 CatalogView 干了什么

`CatalogView.vue`（320 行）是唯一渲染这些页面的组件，职责：

1. 从路由参数 `group/key` 取出配置；配置不存在 → 跳回工作台
2. 同域下**有权限的兄弟页签**渲染成 tab（比如"人事"下员工/计件/工资三个 tab）
3. 按配置渲染表格：列、宽度、枚举标签
4. 分页：`ListPagination`（每页固定 10 条，`total` 来自后端）
5. 有 `filter: 'month'` 就渲染年月器，切换时重新请求
6. 主数据页额外提供新增/编辑弹窗（字段来自 `masterForms`）、删除、SKU 生成
7. 少数"特殊动作"单独分支：工资单人/批量生成、工资发放、由订单生成报价

**老师可能问"这个组件是不是太大了"** → 老实答：320 行里有一半是几个特殊动作的弹窗，通用渲染只占三分之一；更好的做法是把弹窗抽成子组件，这是已知的重构点。

### 5.4 主数据表单也是配置出来的

```ts
masterForms = {
  materials: [
    { key: 'code', label: '编码', required: true },
    { key: 'name', label: '物料名称', required: true },
    { key: 'category', label: '类别', kind: 'category', defaultValue: 1 },
    { key: 'unit', label: '单位', required: true, defaultValue: '米' },
    { key: 'refPrice', label: '参考单价', kind: 'number', defaultValue: 0 },
    { key: 'status', label: '状态', kind: 'status', defaultValue: 1 }
  ], ...
}
```

`kind` 决定控件类型（文本/数字/状态下拉/性别/员工类型/日期/部门/品类），`required` 出必填星号。**加一个主数据字段 = 加一行**。

URL 段到后端资源名的归一由 `masterResource()` 处理（`categories→category`、`processes→process`、`employees→employee`，其余去掉复数 `s`），这样后端一个 `/erp/md/{resource}` 就能覆盖全部主数据。

### 5.5 枚举字典

`api/labels.ts` 共 91 条映射，例如：

```ts
quoteStatus: { 0: {label:'待确认', type:'info'}, 1: {label:'已接受', type:'success'},
               2: {label:'已失效', type:'info'},  3: {label:'已转单', type:'warning'} }
```

好处：状态文案只有一处，不会出现"这个页面叫已完工、那个页面叫生产完成"。
代价（主动承认）：它和 SQL 字段的 `COMMENT` 是两份，新增状态要改两处 —— 比如这次新增 `3 已转单`，两边都补了。

## 6. 业务页举例：订单详情怎么把"状态机"用起来

`OrderDetailView.vue`：

- 顶部显示订单号、客户、交期、金额、状态标签（颜色来自 `labels.ts`）
- 操作按钮按状态 + 权限双重控制：草稿才有"编辑/确认"，确认后才允许"计算成本/建工单/发货"
- 每个动作按钮调一个**动作端点**，不是"改 status 字段"
- 动作请求都带 `requestKey: crypto.randomUUID()`：

```ts
await erpApi.calculateCost(orderId, styleId, crypto.randomUUID())
await erpApi.confirmOrder(orderId)          // 无副作用的确认也走动作端点
```

为什么要 `randomUUID`：这是后端幂等表的键。同一个键重复提交 → 后端返回首次结果，不会重复入账；**新的一次业务就重新生成一个键**，两者不能混。

前端"提交中禁用按钮"只是体验优化，不能当幂等用 —— 用户刷新页面再点，前端状态就没了，后端那层才是兜底。

## 7. 财务页：8 个标签与"同页不同权"

`FinanceView.vue` 的标签是配置数组：

```ts
const tabs = [
  { key:'overview',   label:'总览',     permission:'fn:account:list' },
  { key:'accounts',   label:'账户',     permission:'fn:account:list' },
  { key:'cash',       label:'资金流水', permission:'fn:cashTxn:list' },
  { key:'cashflow',   label:'月度现金流', permission:'fn:cashTxn:list' },
  { key:'receivables',label:'应收',     permission:'fn:receivable:list' },
  { key:'payables',   label:'应付',     permission:'fn:payable:list' },
  { key:'aging',      label:'账龄汇总', permission:'fn:receivable:list' },
  { key:'payments',   label:'收付款',   permission:'fn:payment:list' },
]
const visibleTabs = computed(() => tabs.filter(t => user.can(t.permission)))
```

- 切换标签时不重新加载整页，只调该标签对应的接口（`loadTab` 里一个 `switch`）
- 打开页面时如果 URL 带 `?tab=payments`，会优先切到该标签（菜单可以直达）
- 收付款页需要"账户 / 应收 / 应付"三个下拉，`loadPaymentSources()` 里**逐个按权限判断**再请求，没权限就不发请求

**现场可演示的对比**：`finance` 账号能看到全部 8 个标签，且"收付款"里能登记与确认；`boss` 账号同一页只能看，不能登记。这就是后端 `fn:payment:add` / `fn:payment:confirm` 有没有授给该角色的差别。

## 8. 其他细节（问到就答，问到才讲）

**分页组件**：`ListPagination` 只有 3 个 props/emit，`page-size` 固定 10，`layout="prev, pager, next, total"`。固定每页条数是为了演示时翻页效果一致，后端仍会夹 `pageSize` 上限 500。

**路由细节**：
- `/finance` 有三个 alias（`/finance/receivables`、`/finance/payables`、`/finance/payments`），老链接不会 404
- 详情页路由**由 catalog 配置生成**：`detailRoute` + `detailPermission` 有值就自动注册 `/xxx/:id`，新增详情类型只需在 `router.ts` 的 `detailComponents` 里登记一次
- 未知路径 → 重定向 `/`
- `/:group/:key` 匹配不到 catalog 配置 → 回工作台，不报错

**为什么用 Element Plus**：组件齐全（表格、表单、弹窗、标签、分页），文档中文，和 RuoYi 生态一致；代价是包体不小，按需引入（`unplugin-vue-components`）已经在配置里，但还没做深度裁剪。

**为什么用 Pinia 不用 Vuex**：Vue 3 官方推荐，组合式写法与 `setup` 一致，`store/user.ts` 75 行就够了，没有 mutations 的样板代码。

**为什么前端没有单测**：坦白讲是没排期。现在的保障是 `vue-tsc` 类型检查 + 后端 32 个单测 + 60 项 SQL 自检 + 8 个账号手工过一遍。补的话优先补 `stores/user.ts` 的权限匹配和 `api/client.ts` 的包络解析 —— 这两处逻辑最容易被改坏。

**已知的三个前端债**：
1. `/getRouters` 接口存在但前端没用（导航是静态清单），导致"后端加菜单"和"前端加导航"要改两处；
2. 单据类页面（订单/采购/工单/出货/成本）结构相似度高，还没抽出通用 CRUD 组件，只有主数据那批做了配置驱动；
3. 状态文案在 `labels.ts` 与 SQL `COMMENT` 双份维护。

## 9. 老师可能让你"现场改个东西"

这三件事都能在 1 分钟内做完，提前练一遍，临场不慌。

### 9.1 给列表加一列

1. 打开 `frontend/src/api/catalog.ts`
2. 找到对应页面的 `columns`，加一项：`{ prop: 'refPrice', label: '参考价' }`
3. 保存，Vite 热更新，刷新页面就能看到（前提是后端接口返回了这个字段）

> 讲法：「列是配置出来的，加列不改组件。」

### 9.2 加一个只读列表页

1. `catalog.ts` 某个分组下加一项：`{ title:'XX', path:'/erp/xx/list', permission:'xx:list', columns:[...] }`
2. `App.vue` 的 `links` 加一条导航（path 要跟 URL 一致）
3. `roles.ts` 对应角色的 `navigation` 里加路径（决定它在侧栏的位置）
4. 数据库 `sys_menu` 加菜单 + `sys_role_menu` 授权（否则前端 `can()` 是 false，页面进不去）

> 讲法：「前端三步、数据库两行。菜单是数据，不是硬编码在组件里的。」

### 9.3 加一个按钮权限

1. `sys_menu` 插一条 `F` 类型菜单，`perms='sd:order:xxx'`，父级指向订单菜单
2. `sys_role_menu` 给需要它的角色授权
3. 页面按钮：`<el-button v-if="user.can('sd:order:xxx')">`
4. 后端对应方法加 `@PreAuthorize("@ss.hasPermi('sd:order:xxx')")`

> 讲法：「菜单表就是权限表，`perms` 一列同时决定前端按钮显隐和后端接口放行。」
